## 1. 项目信息 · 原始需求复述

**用户诉求**：现有 Modrinth 模组库 API 直连国内不稳定（卡顿 / 超时），希望**新增 CurseForge 作为替代 / 补充**，且不影响现有 Modrinth 流程；版本号升到 0.8.4；顺带把加载 / 报错 / 空态的体验补好。

**现状（0.8.3）**：`ModrinthClient.java` 提供 `search(query, mcVersion, loader, limit, sort, categories, projectType)` → `List<Hit>`；`ShellView.java` 的 `buildModCenter()` 下有多个 tab（游戏 / 加载器 / 模组 / 整合包 / 资源包 / 光影 / 世界 / 下载队列），「模组」tab 走 Modrinth，「整合包」tab 也走 Modrinth。

## 2. 产品定义

### 2.1 Product Goals（3 个正交目标）

| # | 目标 | 衡量口径 |
|---|---|---|
| G1 | **双源可用**：Modrinth 卡顿时用户能无缝切到 CurseForge 继续找模组 | 新增 CurseForge 入口后，Modrinth tab 行为零变化；国内网络下 CurseForge 搜索 / 详情可完成 |
| G2 | **流程闭环**：CurseForge 的搜索 → 筛选 → 详情 → 安装与 Modrinth 体验一致，装完即进 mods 目录并可管理 | 装完后文件落 `.minecraft/mods`，复用 `ModStore` / `ModIndex`，游戏管理页可见 |
| G3 | **等待可控**：慢 / 断 / 无结果三类场景都有明确反馈，用户知道该做什么 | 「正在加载…」可取消、超时有可行动提示、空态有引导文案 |

### 2.2 User Stories

| # | 故事 |
|---|---|
| US-1 | 作为国内玩家，我想在 Modrinth 卡住时切到 CurseForge 搜同一个模组，以便不用翻墙也能继续装 mod |
| US-2 | 作为挑版本的玩家，我想按 Minecraft 版本过滤、按下载量 / 发布时间 / 更新时间排序、按顶级分类筛选，以便快速找到适配我游戏的那一版 |
| US-3 | 作为谨慎的玩家，我想在详情弹窗里看封面、描述、下载量、官网外链、按 MC 版本分组的版本列表和 Release/Beta/Alpha 标签，以便确认无误再点安装 |
| US-4 | 作为玩家，我想点「安装」就把 `.jar` 装进 mods 目录，以便和现有 Modrinth 装出来的模组一样被管理（启停 / 卸载） |
| US-5 | 作为遇到网络问题的玩家，我想加载时能取消、连不上时看到「检查网络或 API Key」、没结果时看到引导，以便知道下一步该做什么而不是对着空白转圈 |

## 3. 技术规范

### 3.1 Requirements Pool

> P0 = 0.8.4 必做；P1 = 后续迭代；P2 = 锦上添花。

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| P0-1 | **新增 CurseForge 模组库 tab**，独立于现有 Modrinth「模组」tab，不改动 / 不回归 Modrinth 全流程 | P0 | 两个入口并存；Modrinth tab 的搜索 / 详情 / 安装回归全绿 |
| P0-2 | 搜索：关键词 + MC 版本过滤 | P0 | 结果均适配所选 MC 版本；无关键词时给出推荐 / 热门列表而非空白 |
| P0-3 | 排序：下载量 / 最新发布 / 最近更新（明确 CurseForge API 字段映射） | P0 | 三种排序各返回不同且有序的结果集 |
| P0-4 | 分类筛选：Technology / Magic / Adventure / Utility 等**顶级分类**胶囊 | P0 | 胶囊可多选 / 取消，结果与所选分类一致 |
| P0-5 | 详情弹窗：封面 + 描述 + 下载量 + 外链（`curseforge.com/mods/xxx`）+ **按 MC 版本分组的版本列表** + 类型标签（Release / Beta / Alpha）+ 安装按钮 | P0 | 六个要素齐全；外链可点开；版本按 MC 版本分组展示 |
| P0-6 | 安装：下载 `.jar` 到 mods 目录，复用 `ModStore` / `ModIndex`；失败不留半成品 | P0 | 装完文件在 mods 目录、索引有记录、游戏管理页可见；校验失败无残留损坏文件 |
| P0-7 | API Key：用户配置在 `~/.gbl/curseforge.key`；首次运行 / 未配置时提示（或经 `SettingsStore` 落配置项） | P0 | 未配置时给出明确指引而非静默失败；配置后即刻生效 |
| P0-8 | 版本号升 **0.8.4**：`LauncherApp.VERSION` + Agent / UA 字符串同步 | P0 | 标题栏 v0.8.4；源码无 0.8.3 残留；UA 含 0.8.4 |
| P0-9 | UX 改进：①「正在加载…」加**取消按钮**且取消后清半成品；②超时错误改为可行动文案（如「CurseForge 暂时连不上，检查网络或 API Key」）；③空状态文案优化（区分「没搜到 / 未配置 Key / 加载失败」） | P0 | 三种状态各有对应文案；取消后无脏状态；错误不甩异常堆栈 |
| P0-10 | 自测扩充与回归：既有自测两趟（浅色 / 深色）全绿，新增 CurseForge tab 渲染 / 空态 / 详情弹窗断言 | P0 | 用例总数 ≥ 原有 + 新增；既有类名与点击路径不破坏 |
| P1-1 | 分类与排序结果缓存，减少重复请求 | P1 | 同参数二次进入不重复打接口 |
| P1-2 | 整合包 tab 也接入 CurseForge 作为补充源 | P1 | 整合包可双源切换 |
| P2-1 | CurseForge 分类 / 模组名中文别名展示 | P2 | 与现有中文别名口径一致 |

**P0 共 10 条**（P0-1 ~ P0-10）；P1 2 条；P2 1 条。

### 3.2 UI Design Draft（文本描述）

```
下载 → 模组中心
├─ 现有 tab：游戏 / 加载器 / 模组(Modrinth) / 整合包 / …（保持不动）
└─ 新增 tab：「CurseForge」（或「模组」下的子 tab，形态见 Q1）
   ├─ 顶部工具条：搜索框 + MC 版本下拉 + 排序下拉（下载量 / 最新发布 / 最近更新）
   ├─ 分类胶囊行：Technology / Magic / Adventure / Utility / …（可多选，选中态高亮）
   ├─ 结果区：与 Modrinth 同款封面卡片网格
   │    每卡：封面 / 标题 / 简介 / 下载量 / 分类标签
   ├─ 加载态：「正在加载…」+ 「取消」按钮
   ├─ 错误态：「CurseForge 暂时连不上，检查网络或 API Key」+ 重试 / 去配置入口
   ├─ 空态：按原因分文案（没搜到 → 换关键词；未配置 Key → 去配置；加载失败 → 重试）
   └─ 点击卡片 → 详情弹窗（复用现有弹窗壳）
        ├─ 头部：封面 + 标题 + 下载量 + 外链「在 curseforge.com 查看」
        ├─ 简介 + 分类标签
        └─ 版本区：按 Minecraft 版本分组，每行 = 类型标签(Release/Beta/Alpha)
                    + 版本名 + 日期 + 「安装」按钮
```

- 视觉完全复用 Modrinth 的卡片网格 / 弹窗 / 标签 / 胶囊样式，不造第二套组件。
- 所有网络请求在后台线程，取消 / 进度 / 结果经 FX 线程回填；错误文案带下一步动作。

### 3.3 Open Questions（待 team-lead 拍板）

| # | 问题 | PM 倾向 |
|---|---|---|
| Q1 | **入口形态**：顶层新增「CurseForge」tab，还是「模组」tab 下加「Modrinth / CurseForge」子 tab？ | 倾向顶层新 tab —— 最小变更、零回归风险；子 tab 更省空间但要动现有结构 |
| Q2 | **API Key 存放**：只读 `~/.gbl/curseforge.key` 文件，还是同时进 `SettingsStore` 提供设置页输入框？ | 建议两者都支持（文件为准、设置页可选填），首启未配置给一次性引导 |
| Q3 | **排序字段映射**：下载量 / 最新发布 / 最近更新分别对应 CurseForge 的哪些字段与 `sortField` / `sortOrder` 取值？ | 请架构按官方 API 实证确认后落表，PRD 不预设 |
| Q4 | **顶级分类集合**：以 CurseForge 的 classId / categoryId 哪一层为准？是否需要固定白名单？ | 建议固定 6~8 个常用顶级分类，避免全量拉取 |
| Q5 | **弹窗复用**：是否复用 Modrinth 详情弹窗单例（按当前数据源分支渲染 CurseForge 版本行）？ | 倾向复用单例 + 数据源分支，避免两套弹窗 |
| Q6 | **安装冲突**：同名 `.jar` 已存在时跳过并提示，还是覆盖 / 备份？是否写 `ModIndex` 索引记录？ | 倾向跳过并提示；索引按现有 Modrinth 口径记录 |
| Q7 | **整合包 tab** 本版是否也要接 CurseForge？ | 倾向列 P1-2 后置，0.8.4 只做模组库 |

## 4. 范围边界

- **不改**：现有 Modrinth 模组库 / 整合包流程、加载器 / 游戏 / 下载队列等既有 tab、账号 / 启动 / 皮肤链路。
- **不引入**第三方库；网络沿用现有 `HttpClient` + UA 口径。
- 本 PRD 只描述需求与验收，不含代码实现。
