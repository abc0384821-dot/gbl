## 1. 原始需求复述

**用户原话**（1.1.5）：
> 1. UI 太丑了；2. 有个下拉框不符合 GBL 风格，但那种下拉框的动画效果可以，可以把这种动画效果应用到所有下拉按钮，只不过动画可以快点；3. 去参考 HMCL 吧；4. 操作又开始卡了。

**录屏核对事实**（作为本文事实基线）：

- 主界面为深色 GBL 风格（左侧导航、绿色主色、圆角卡片），当前处于 1.1.4 新增的「多人联机」页。
- 「日志与诊断」是 **JavaFX 原生 `TitledPane`**（`MultiplayerPage.java` 约 433 行）：标题栏为浅灰 / 白色不透明横条，三角箭头为原生样式，与深色主题严重不搭；但它展开 / 收起有**纵向动画**，用户认可该动画本身。→ 对应用户说的「下拉框」与「动画效果」。
- 「节点配置」里的「使用内置节点（推荐）」是绿色 `ComboBox`，样式基本符合 GBL。（`nodeMode`，约 326 行）
- 「网络体检」区颜色偏杂（黄色「未知 / 不可用」），多处绿色胶囊标签，观感拥挤。
- 「参考 HMCL」理解为：深色主题、紧凑布局、统一控件外观（HMCL 的视觉风格，非引入 HMCL 代码 / 控件库）。

**硬约束（不可违反）**：

1. 全中文表述，避免技术黑话；所有错误提示统一为「**什么失败 + 为什么 + 下一步**」三段式。
2. **不改 logo**（逐字节沿用桌面 GBL 0.9.5 原件），**不改四处同源图标**。
3. 每次发版必须新建**独立 release** 并同步发布到**官网 + Gitee + GitHub**（用户已授权自动执行，本文不重复征询）。
4. 版本号与 build 统一 `1.1.5`，显示 `v1.1.5`（`LauncherApp.java:17` 的 `VERSION` 及 `DISPLAY_VERSION` 同步）。

## 5. UI 改动描述（改哪个控件 → 改成什么）

> 样式统一落在现有 `src/main/resources/com/mclauncher/theme.css`（及 `popup-dark.css`），不新增 UI 依赖。

1. **「日志与诊断」折叠面板**（`MultiplayerPage.java` 约 433 行的 `TitledPane`）
   - 现状：原生浅灰 / 白标题横条 + 原生三角箭头，与深色主题冲突。
   - 改为：GBL 自定义折叠控件（深色标题条 + 圆角 + `card` 同款边框 / 内边距），箭头改为自定义图形并随展开 / 收起旋转；标题文字用现有中文样式。
   - 动画：纵向展开 / 收起，**150ms（区间 120–180ms）**，缓动曲线。

2. **所有下拉按钮 / 折叠入口**（`ComboBox` 弹出层、日志面板、其他可折叠卡片）
   - 统一采用与上述面板相同的展开动效与时长（150ms）；`ComboBox` 弹出层改为 GBL 深色圆角样式，去除原生白底。
   - 「节点配置」的绿色 `ComboBox`（`nodeMode`）**保持现有 GBL 风格**，仅套用统一动效，不改配色与行为。

3. **「网络体检」区**（`MultiplayerPage.java` 约 368 行起）
   - 现状：黄色「未知 / 不可用」+ 多处绿色胶囊，颜色偏杂、拥挤。
   - 改为：状态色收敛到既定 token——正常（绿）、警告（黄）、异常（红）、未知（灰）；减少同时出现的高饱和胶囊，用留白 / 分组替代堆叠。

4. **整体布局（参考 HMCL）**
   - 收紧卡片内边距、控件间距与行高，使联机页与主界面更紧凑；控件（按钮 / 输入框 / `ComboBox` / 标签）外观统一到同一套样式。

**不变项**：左侧导航结构、绿色主色、圆角卡片语言、logo、四处同源图标、1.1.4 联机功能与交互口径——均保持不动。

## 6. 验收标准（可测）

### 6.1 视觉与交互

- AC-1：深色主题下，「多人联机」页及主界面**无任何浅灰 / 白色原生横条或原生三角箭头**；日志面板标题条为 GBL 深色样式。
- AC-2：所有下拉 / 折叠控件动画时长经抽帧或代码核对落在 **120–180ms**，各控件一致；连续快速点击 5 次无动画叠加、无跳变 / 闪白。
- AC-3：体检区仅出现既定状态色，黄色 / 绿色 / 红色 / 灰色用法一致；无过量胶囊堆叠。
- AC-4：对照 HMCL 深色主题与紧凑布局，主界面与联机页无违和控件；logo 与四处图标与 1.1.4 文件哈希一致。

### 6.2 流畅度（G3 硬门槛）

- AC-5：页面切换（含进出「多人联机」页）**无明显肉眼卡顿**，单击到界面响应可感延迟控制在约 100ms 内。
- AC-6：在 500ms 房间轮询持续运行 + 日志抓取进行中，输入框打字、列表滚动、下拉展开均不出现掉帧 / 停顿。
- AC-7：网络体检过程中界面保持可操作（可切页、可点击），体检完成后结果异步回填；无「界面无响应」弹窗或假死。
- AC-8：代码核对——轮询、日志抓取、体检等重活**不在 JavaFX 应用线程执行**，跨线程 UI 更新统一走线程切换（如 `runFx`）；频繁刷新已合并 / 节流。

### 6.3 文案与发布

- AC-9：本次涉及的失败提示均为中文「什么失败 + 为什么 + 下一步」三段式，无堆栈、无黑话。
- AC-10：`VERSION` / build 为 `1.1.5`，界面显示 `v1.1.5`，源码无 `1.1.4` 字样残留。
- AC-11：发版产出**独立 release**，并同步发布到官网 + Gitee + GitHub；三处版本号与安装包一致。
