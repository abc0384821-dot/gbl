# GBL 0.8.8「装完看得见 · 前置跳页自选 · 详情与加载器对齐 HMCL」增量 PRD

> ★★ **2026-11-07 用户当面澄清（覆盖本文早期 R-03 口径）**：用户原话「我要点那个前置模组的安装，不是立马下载，而是跳转到那个前置模组的页面，让用户自己选」。**跳页是期望行为，不是 bug**；早期把它读成「用户抱怨跳页、要改成一点即装」是误读。因此 **R-03「直装·不跳页」全链路作废**，改为「点前置卡 → 跳到该前置模组页面 → 用户自己挑版本 → 绝不自动下载」。本文下方若仍有「直装 / 一点即装 / 不跳页」残留字样，一律以本注记与 §3 R-03 行为准。其余需求（依赖卡片化、图标、四分区、依赖数据完整性、三类内容版本分组与推荐、加载器 tab 时机与可用性）不变。0.8.8 已按此发布。

## 1. 产品目标与范围边界

**产品目标（一句话）**：让 0.8.8 在「装完立刻看得见、前置依赖看得清且一点就装、三类内容详情与 HMCL 一致、加载器版本一进就有」四件事上对齐 HMCL，作为 0.8.8 发布门禁的验收基准。

### 1.1 本版只做什么

用户在真机 0.8.7 上报的 9 项（第 2 节 US-1 ~ US-9）：下载内容与游戏管理的一致性、前置依赖卡片化与直装、依赖数据完整性、三类内容详情版本分组、加载器 tab 加载时机与 Fabric/Quilt 可用性、版本号与发布物料。**只做修复与补齐，不扩展新领域。**

### 1.2 明确「不改什么」（Out of Scope）

以下 0.8.7 已验收项本版**一律不动**，回归测试只验证「不破」：

- 皮肤 3D 预览、账号体系（离线 / LittleSkin / 微软）、下载队列、WebP 封面、中文别名（`ModAliases`）
- Modrinth / CurseForge 模组库主流程（搜索、排序、分类、封面卡片网格、详情弹窗结构）
- 整合包导入、资源包 / 光影 / 世界三内容库的浏览与搜索、OptiFine 独立加载器、Forge / NeoForge 安装器
- 模组版本级前置依赖「三分类」的**数据语义**（本版只改展示形态与交互，不改分类规则）
- Fabric meta 走 BMCLAPI 镜像的既有修复、启动链路、设置页与目录约定
- 不新增内容库、不新增第三方依赖、不改包名 / 自测既有类名与点击路径、不重构服务层

### 1.3 优先级定义

P0 = 0.8.8 发布门禁必过；P1 = 本版尽量做，未做完不阻断发布（见 Q6）。

## 2. 用户故事与验收标准

> 每条验收标准均可写成自动断言（Snapshot / 单元测试）或明确的真机步骤。

**US-1（对应上报 1 · P0 缺陷）装完即可见**
作为在下载页装模组的玩家，我希望从详情弹窗点「安装」后，到「游戏管理」页立刻看到它并能启停 / 卸载，以便不用去文件管理器确认装没装成功。
- ① 真机：选当前游戏 → 下载页「模组」详情弹窗安装任意 1 个模组 → 切到「游戏管理」，「已安装模组」段出现该模组（名称 / 图标 / 启用开关 / 卸载按钮），不再显示空态「这个游戏还没装任何模组」。
- ② 真机：分别对资源包 / 光影 / 世界从内容详情弹窗安装 1 个 → 「游戏管理」对应三段各自出现条目，可启停（世界按现有口径）/ 卸载。
- ③ 自测断言：模拟安装回调后 `gameMgmtModsBody` 与三个内容段的子节点数 ≥ 1 且空态节点不可见；卸载后回到空态。
- ④ 真机：安装后不重启启动器、不手动刷新，切页一次即生效。

**US-2（对应上报 2 · P0 UI）前置依赖卡片化**
作为看不懂一行小字的玩家，我希望前置依赖是带模组图标的大卡片，一眼看清「缺什么、装没装」，以便不会漏装前置导致进游戏崩溃。
- ① 真机：打开一个有前置的模组详情弹窗，依赖区渲染为卡片列表，每卡含**模组图标**（取不到时用占位图）、名称、分类标签（必须 / 可选 / 已内置 / 不兼容）、状态与动作区。
- ② 自测断言：依赖卡节点存在、图标节点存在、卡片最小高度 ≥ 64px（明显大于现状单行文字），且分类分区标题仍在。
- ③ 真机：已装的显示「✓ 已安装」，外部依赖显示灰字「外部依赖，需自行准备」，不出现空行 / 空白卡。

**US-3（对应上报 3 · P0 功能）点「安装」即直接安装，不跳转**
作为正在装模组的玩家，我希望点前置依赖卡片的「安装」就把它装进当前游戏并有进度 / 结果反馈，以便不被丢到搜索页重新找一遍。
- ① 真机：点击未装前置的「安装」→ **不切换页面、不打开新弹窗、不跳搜索页**；按钮变「安装中…」，结束后变「✓ 已安装」，并有 toast 结果。
- ② 真机：装完的文件落在当前游戏的 `.minecraft/mods`，「游戏管理」的已装模组段同步出现（与 US-1 联动）。
- ③ 自测断言：点击依赖安装按钮后 `currentPage` 不变、页面标题不变；成功回调后该卡片状态文案为已安装。
- ④ 真机：找不到适配当前游戏版本的版本时给出明确提示（含模组名与 MC 版本），按钮恢复可点，不静默失败。

**US-4（对应上报 4 · P1）覆盖整合包、资源包、光影、世界**
作为玩整合包和材质 / 光影 / 地图的玩家，我希望上面两件事（依赖卡片化 + 一点即装）在整合包和三类内容库里也一样，以便全站体验一致。
- ① 真机：整合包详情弹窗、资源包 / 光影 / 世界详情弹窗中，凡有依赖关系均按 US-2 的卡片形态渲染，且「安装」按 US-3 直装到当前游戏。
- ② 自测断言：四类详情弹窗的依赖区节点类名 / 结构与模组详情一致（同一套渲染组件）。
- ③ 边界：无依赖数据的类型保持不显示依赖区（不出现空板块），不报错。

**US-5（对应上报 5 · P0 数据）依赖数据完整、与 HMCL 口径一致**
作为玩家，我希望 HMCL 里能看到的前置在 GBL 里也都能看到，以便不因漏提示而装出一个跑不起来的组合。
- ① 自测断言：以 Q2 约定的样本清单为准，逐个项目 / 版本比对依赖条数与类型，GBL 解析结果与样本零差异（不漏 required、不误吞 optional、embedded 不给安装按钮）。
- ② 真机：抽取用户反馈中「HMCL 有、GBL 没有」的模组，打开对应版本详情，前置依赖区出现该前置。
- ③ 自测断言：依赖反查失败 / 字段缺失时按 projectId 兜底显示，**绝不隐藏整个依赖板块**；切换版本时依赖区随版本重建。

**US-6（对应上报 6 · P0 UI）三类内容详情的版本分组与推荐徽标**
作为装光影 / 资源包 / 世界的玩家，我希望详情弹窗的版本列表跟模组和整合包一模一样（按 Minecraft 版本分组 + 推荐徽标），以便快速挑到适配我游戏的那一版。
- ① 真机：打开光影详情，版本区显示「Minecraft 1.20.1 · 推荐 · 共 N 个版本」这类**分组标题 + 「推荐」徽标**，不再是「版本列表 · 共 31 个」平铺（r5.9.3 / r5.9.2…）。
- ② 真机：资源包、世界详情同样分组；当前游戏版本对应的组置顶并标推荐。
- ③ 自测断言：三类内容弹窗的版本分组头节点、推荐徽标节点、组内版本行节点数量 > 0，且与模组 / 整合包详情使用同一分组渲染口径。
- ④ 真机：组内版本行保留类型标签（Release / Beta / Alpha）、日期、大小、安装按钮与三态反馈，点击安装仍能装成功。

**US-7（对应上报 7 · P0 缺陷）加载器 tab 进入即加载**
作为要装加载器的玩家，我希望一进「加载器」tab 各张卡就显示可选版本，以便不用先去切换一次「当前游戏」下拉。
- ① 真机：冷启动 → 直接点「下载」页 → 切到「加载器」tab，**不碰当前游戏下拉**，5 张卡的版本下拉均出现可选版本（非「加载中…」、非空白）。
- ② 自测断言：进入加载器 tab 后触发版本拉取的调用次数 ≥ 1，且不依赖下拉 `onAction` 事件。
- ③ 真机：切换当前游戏后版本列表按新游戏刷新，不残留上一个游戏的结果。

**US-8（对应上报 8 · P0 缺陷）Fabric / Quilt / LegacyFabric 全源可用、要快、失败要看得见**
作为国内玩家，我希望 Fabric / Quilt / LegacyFabric 在「加载器」tab 里无论下载源是官方还是 BMCLAPI 都能拉到版本且够快，以便不像现在这样恒空白（而「安装新游戏」弹窗里却能出来）。
- ① 真机（官方源）：录屏口径 0 秒 5 张卡空白 → 数秒内 Forge / NeoForge **和** Fabric / Quilt / LegacyFabric 全部出现版本号；不再出现「Forge=66.1.5、NeoForge=26.3.0.101 有了，Fabric 系恒空白」。
- ② 真机（切到 BMCLAPI 源后重进 tab）：同样 5 张卡都有版本。
- ③ 真机：故意断网 / 让接口失败，失败卡显示**可见错误文案 + 重试入口**（如「版本列表没拉出来，检查网络或换个下载源」），不得空白、不得无限「加载中…」、不得只是一闪而过的 toast。
- ④ 自测断言：单卡失败不影响其他 4 张卡继续加载；重试后可成功回填，默认选中最新稳定版。
- ⑤ 真机：「加载器」tab 与「安装新游戏」弹窗的 Fabric 版本结果一致，且加载耗时不劣于弹窗。

**US-9（对应上报 9 · 发布）版本号 0.8.8 与发布物料**
作为发布负责人，我希望版本号升到 0.8.8 并同步 Gitee release 与官网，以便用户拿到的是同一版口径。
- ① 源码：`LauncherApp.VERSION = "0.8.8"`，窗口标题显示 `v0.8.8`，Agent / UA 字符串同步引用版本号，源码内无 0.8.7 残留。
- ② 发布：Windows 便携包上传 Gitee release，标签与文件名含 0.8.8。
- ③ 官网：4 页版本号引用 / 更新说明同步到 0.8.8；与 Gitee release 的版本号一致。

## 4. UI 设计要点（文字描述）

### 4.1 前置依赖卡片（对齐 HMCL）

```
依赖区：分区标题「必须安装 / 可选安装 / 已内置 / 不兼容」（沿用 0.8.7 三分类，标题文案可微调）
└─ 一张依赖卡（最小高度 ≥ 64px，明显大于现状一行小字）
   ├─ 左：模组图标（WebP / 封面，48~64px；取不到用纯代码占位图）
   ├─ 中：模组显示名（主行，card-title 级字号）
   │      副行：分类标签（必须 / 可选 / 已内置 / 不兼容）+ 作者或 MC 版本等补充信息
   └─ 右：状态 / 动作
         · 已装 → 「✓ 已安装」（绿色，按钮位不出现）
         · 未装 → 「安装」主按钮（点击后「安装中…」→ 成功「✓ 已安装」/ 失败恢复可点 + 提示）
         · 外部依赖 → 灰字「外部依赖，需自行准备」
```
- 复用现有 `card` 样式与 `Icons` / 封面加载能力，新增独立样式类，不造第二套反馈组件（进度 / 结果仍走 toast + 状态行）。
- 依赖卡随选中版本联动重建；反查不到图标时用占位图，绝不因单条数据缺失隐藏整块。

### 4.2 三类内容详情：版本分组与推荐徽标

```
版本区（与模组 / 整合包详情完全同款）
├─ 组头：「Minecraft 1.20.1」 + 「推荐」徽标(tag-release) + 「共 N 个版本」  ← 当前游戏版本组置顶
│   └─ 版本行：类型标签(Release/Beta/Alpha) · 名称 · 加载器 tags · 日期 · 大小 · 「安装」按钮
├─ 组头：「Minecraft 1.19.2」 + 「共 N 个版本」
│   └─ …
└─ 组头可折叠；默认展开推荐组
```
- 现状「版本列表 · 共 31 个」的平铺渲染改为分组渲染；组头组件与模组 / 整合包复用同一个。
- 版本行的安装回调仍走 `dispatchInstall` 按 `ContentStore.Kind` 分派，三态反馈（进行中 / 成功 / 失败）不变。

### 4.3 加载器 tab 的加载态 / 失败态

```
一张加载器卡：名称 + 状态 + [版本下拉] + [安装/卸载]
下拉三态：
  · 加载中 → 「正在拉取版本…」（可见文案，不是空白；不得永久停留）
  · 成功   → 可选版本列表，默认选中最新稳定版，按钮可点
  · 失败   → 卡内可见错误文案（如「版本列表没拉出来，检查网络或换个下载源」）
             + 「重试」按钮；错误态常驻直到重试成功
```
- 5 张卡独立拉取、互不阻塞；单卡失败不影响其他卡。
- 不在页面上堆新的进度条组件；沿用现有状态条 / toast / 卡片内文案。

## 5. 非功能要求
